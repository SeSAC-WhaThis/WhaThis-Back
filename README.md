# WhaThis

SeSAC **1차 팀 프로젝트**로 Wadiz를 벤치마킹한 **e-Commerce / 크라우드 펀딩** 웹 서비스 **WhaThis**의 백엔드 레포지토리입니다.

짧은 개발 기간을 고려해 **펀딩(Funding) 기능을 우선 구현**하였습니다.

### 프로젝트 목적

본 프로젝트는 메이커가 프로젝트르 등록하고, 서포터가 해당 프로젝트에 펀딩 형태로 참여할 수 있는 크라우드 펀딩 플랫폼을 구현. 

### 프로젝트 배경

와디즈 등 기존 크라우드 펀딩 서비스는 프로젝트 탐색 → 펀딩 참여 → 결과 확인이라는 명확한 사용자 흐름을 갖는다. 본 프로젝트는 이러한 구조를 참고하여 핵심 기능 위주의 MVP를 개발함으로써, 향후 확장 가능한 서비스 기반을 마련하고자 합니다.

### 프로젝트 목표


1차 MVP에서는 펀딩 핵심 플로우를 제공하는 데 집중하고, 기간(약 2주) 내에 펀딩 사이클이 정상적으로 동작하는 웹 서비스를 구현하는 것을 목표로 했습니다.

### 김수환
#### 1. N+1 문제 해결 및 대량 데이터 처리를 위한 무한 스크롤(Pagination) 구현
- 상품 목록 조회 시 판매자(`Seller`)와 카테고리(`Category`) 정보를 함께 가져와야 하는데, JPA의 지연 로딩으로 인해 발생할 수 있는 `N+1` 문제를 `JOIN FETCH`를 사용하여 단 한 번의 쿼리로 최적화함.
- 초기에는 단순 리스트(`List`) 반환이었으나, 데이터 증가에 대비해 `Pageable`을 적용한 무한 스크롤 방식으로 리팩토링함.
- 이 과정에서 API 명세 변경이 프론트엔드에 미치는 영향(렌더링 깨짐)을 파악하고, DTO(`PageResponse`)를 재설계하여 클라이언트와의 통신 규약을 명확히 함.

#### 2. 비즈니스 유연성을 위한 리뷰(Review) 시스템의 의존성 분리 (Refactoring)
- 기존에는 리뷰가 주문(`Order`) 테이블에 강하게 종속(`Foreign Key`)되어 있었으나, 주문 건당 리뷰가 아닌 **사용자당 제품 1회 리뷰 등으로 요구사항이 변경**됨에 따라 엔티티 관계를 재설계해야 했음.
- `Order`와의 연관관계를 끊으면서 DB 제약조건으로 해결되던 '중복 리뷰 방지' 로직이 사라지자, 이를 **애플리케이션 레벨**에서 검증 로직으로 직접 구현하여 데이터 무결성을 보장함.
- 단순한 CRUD가 아니라 비즈니스 요구사항 변화에 맞춰 유연하게 아키텍처를 변경함.
